# 出摊计算器 · 手机版

面向摆摊场景的**离线收银与余货统计工具**。单个 HTML 文件，添加到手机主屏幕后
即为全屏应用：不联网、不上传、无需注册、无需服务器。

**所有数据保存在本机浏览器存储中，不经过任何网络。**

---

## 快速开始

1. 将 `出摊计算器.html` 传到手机（云盘、文件传输助手、数据线均可）
2. 用手机浏览器（推荐 Chrome）打开该文件
3. 点击浏览器菜单 →「添加到主屏幕」
4. 之后从桌面图标进入即为全屏应用

详细步骤、常见问题与数据备份方式见 [`手机安装说明.md`](手机安装说明.md)。

> 文件体积约 140KB，无任何依赖，不需要联网安装。

## 功能

### 收银

- 商品以图片网格展示，点击一次增加一件，支持分类筛选与搜索
- 购物车每行提供 `−` / `＋` 微调
- 数量变动后实时展示金额明细阶梯（原价 → 折扣 → 满减 → 抹零 → 应收）
- 移动端底部固定显示「合计 + 结算」，购物车以底部抽屉展开

### 折扣

- **比例折扣**：如 `9折`、`8.5折`
- **满减**：如 `满100减10`、`满200减30`，支持多档配置
  - 多档同时满足时，**自动选取对顾客最有利的一档**（非逐档累加，亦非匹配第一档）
- **单品优惠**（在「商品」页单独设置）
  - **第二件半价**：买 2 件时第 2 件半价；买 4 件时第 2、4 件均半价
  - **第 N 件 X 折**：例如「第 3 件 5 折」，买 6 件时有 2 件按 5 折计算
- **套装价**（在「更多 → 套装价」配置）：跨商品的「任意 3 件 20 元」
  - 仅在低于单买总价时生效；未凑满部分按原价计算
  - 优惠按单价加权分摊到各行，保证明细各项之和等于优惠总额
- **可叠加**：单品/套装 → 比例折扣 → 满减 → 抹零
  - 比例折扣与满减同时启用时，结算前会展示各档明细并需确认
- **尾数取整**：精确到分 / 抹零到角 / 抹零到元 / 凑整到元

### 结算

- 可记录顾客实付金额并自动计算找零，提供 ¥50 / ¥100 / ¥200 快捷输入
- 实付低于应收时会拦截；留空表示正好收齐
- 完成后生成回执：单号、明细、原价、优惠金额、折扣率、找零

### 撤销

- **软撤销**：单据标记为已撤销，数据不删除，库存自动回补
- 已撤销单据不计入销售额，但保留在记录中可随时查阅（含撤销原因）

### 库存

- 实时展示每款商品的带来 / 已售 / 剩余
- 剩余低于预警线的商品标红，可筛选「仅显示库存不足」
- 每款商品提供库存流水：初始、补货、售出、撤销回补，逐笔可追溯
- 出摊中途进货使用「补货」；盘点差异可填负数修正

### 统计

- 实收总额、原价总额、优惠金额、订单数、销售件数、客单价
- 商品销量排行、每小时成交分布
- 完整交易流水（含已撤销），支持撤销与导出 CSV

### 多场次

同一商品在不同场次中的「带来数量」不同，因此按场次分别记账：

- 打开应用即自动存在一个进行中的场次，顶部始终显示当前场次
- 进入下一场活动时点击「开新一场」，上一场自动收尾，新单据归入新场次
- 点击「收摊」结束当前场次，其结算结果随之固定
- 可随时回看任意一场的历史结算表

### 收摊结算

- 一键生成：**带来 120 件，售出 73 件，剩余 47 件，共 N 单，实收 ¥xxxx**
- 逐商品明细：开场库存 / 场内进货 / 带来 / 售出 / 剩余 / 单价 / 销售额
- 支持打印 / 存为 PDF，也可导出 CSV（文件名含场次名）

### 数据

- 导出 / 导入备份（JSON），可选「替换」或「合并」
- 商品图片自动压缩至 900px、JPEG 质量 82%，单张约 30~60KB
- 可直接调用手机相机或相册

## 数据与安全

**数据存储位置**：浏览器本地存储（localStorage），容量约 5MB。

**没有服务器**，因此：

- 数据不会离开这台手机
- 换手机、清除浏览器数据前**必须**先导出备份
- **无备份则无法找回**

**应用会在启动时自检存储**：若浏览器不允许本地存储（常见于从本地文件打开时），
会立即弹窗提示，不会出现无提示状态下记录整场后数据丢失的情况。

## 设计说明

**1. 金额一律以「分」为单位进行整数运算。**
不使用浮点数存储金额。浮点运算在 `0.1 + 0.2` 这类场景下会产生误差，
涉及金额的计算不宜依赖浮点精度。

**2. 库存通过「流水账」推导，而非存储单一 current 字段。**

```
当前库存 = 初始 + 补货 + 盘点修正 + 销售净额
销售净额 = Σ(sale 流水) + Σ(void_return 流水)
```

已撤销单据的两笔记录（`-qty` 与 `+qty`）自动抵消，无需按单据状态特判。
开发过程中曾出现两种错误写法：只累加补货而遗漏销售扣减；
以及按「已完成单据」扣销售、另加撤销回补，导致库存凭空翻倍。

**3. 折扣顺序固定：单品/套装 → 比例折扣 → 满减 → 抹零。**
叠加时「满减门槛按折后价判定」。顺序固定是刻意设计。
实收金额为最终定价，优惠金额由 `原价 − 实收` 反推，
确保 **原价 − 优惠 = 实收** 恒等式始终成立。

**4. 套装价支持跨商品凑件数，且仅在更低时生效。**
「任意 3 件 20 元」是跨商品的：2 个 A + 1 个 B 同样计为 3 件。
同一套装下所有商品的件数合并计数，并按单价从高到低优先纳入套装（顾客优惠最大）。
优惠按「被覆盖件数 × 单价」加权分摊回各行，最后一行承担舍入差额。

**5. 场次分账以「流水 ID」作为开场边界，不使用时间戳。**
时间戳精度仅到秒，同一秒内的「开场 → 上架 → 卖出」会被错误归属。

**6. 撤销采用软撤销。**
负数冲账单会导致「订单数」与「销售额」都需要额外扣减才准确，
在报表核对时容易产生不一致。

**7. 启动时自检存储，而非假设可用。**
通过 `file://` 打开时，各浏览器对本地存储的策略不一致（部分直接禁用）。
支持并不代表当前上下文允许，因此启动时实际读写验证一次。

**8. 图片压缩使用 canvas。**
浏览器自带 canvas，因此拍照或选图后可压缩至 900px、JPEG 质量 82%，
5MB 存储约可容纳 80~150 张商品图。

**9. 弹窗必须具备底栏。**
移动端「新增商品」弹窗曾出现底部按钮被挤出屏幕的问题。根因有三层：
弹窗结构允许「无底栏」状态存在；底栏通过 `flex` 计算高度在移动端 WebView 中出错；
表单过长导致最后一行紧贴底栏。修复方式：底栏无条件创建（调用方未提供按钮时
自动补充「关闭」）、`flex:0 0 auto` 不可压缩并按安全区设置内边距、
高度使用 `100dvh`、正文区 `min-height:0` 可滚动、表单采用双列减少高度。
并新增 5 项测试守护「底栏不可消失」。

**10. 手机浏览器截图核对时注意**：`--window-size` 不等于 CSS 视口宽度，
直接按窗口截图会裁掉右侧，看起来像布局溢出。应先用 iframe 固定宽度
再测量 `scrollWidth`。

### 使用前请注意

由于代码主要由 AI 生成，**在用于真实资金往来之前，建议自行审查关键路径**：

- 主文件 `出摊计算器.html` 中的计价函数（决定收顾客多少钱）
- 同文件中的库存推导与撤销逻辑（决定库存与销售额是否对得上）

项目自带 75 项自动化测试（57 + 18），可作为审查的起点：

```bat
python run_tests.py
```

### 若使用 AI 继续维护本项目

建议在提示中提供以下上下文（这些是最容易改错的地方）：

- **账目口径**：金额以「分」存整数；库存按流水推导；
  折扣顺序为「单品/套装 → 比例折扣 → 满减 → 抹零」；
  实收为最终定价，优惠额由 `原价 − 实收` 反推（恒等式必须成立）
- **场次边界**：使用流水 ID，不要改用时间戳
- **测试先行**：改动计价或库存逻辑后，先跑测试再提交
